## 0. Definitions and the target

| Term | Meaning |
|---|---|
| **Job / vacancy (app)** | One canonical vacancy in the app database. Archive vacancies are deduplicated in the lake; snapshot listings are one per listing; a vacancy seen on several sites or in several crawls counts once. Cross-source matches merge into one job. |
| Source record | One posting on one page (archive) or one snapshot row. |
| Observation | One sighting of a posting in one capture. Re-captures add observations, never vacancies. |
| Campaign | Copies of one page for many places (SEO); stored as one vacancy without a single place. |
| Status | From evidence only (§4). "Verified active" requires a permitted live check, which no source has. |

**The 100,000 target counts unique canonical vacancies in the app across all permitted
sources (archive + snapshot + any future licensed or permitted source), after
cross-source deduplication, historical and current alike.** A separate, stricter target
is the number of *verified active* vacancies, currently 0.

## 7. Path to 100k, 500k, 1M

See SOURCE_ASSESSMENT.md §1. In short: without permission, only the archive grows
(historical, ESTIMATE 13–20 more complete crawls for 100k). With permission, Kemnaker's
Karirhub (press: 753,500 vacancies Jan–Sep 2025) or a licensed feed (Techmap, vendor:
≈ 32k new Indonesian postings/month, display rights needed) each exceed 100k after
deduplication and are the only plausible routes to 500k–1M and to *current* listings.
